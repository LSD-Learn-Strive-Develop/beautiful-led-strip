## Быстрый повторный запуск

На Raspberry Pi:

```bash
cd ~/dev/beautiful-led-strip
sudo .venv/bin/python main.py
```

Если бот уже работает в tmux, сначала вернитесь в существующую сессию:

```bash
tmux ls
tmux attach -t leds
```

Не запускайте вторую копию бота с тем же токеном: это может вызвать конфликт получения обновлений Telegram.

## Что проверили

- Разбор конфигурации прокси, создание сессий для прямого подключения, HTTP и SOCKS5.
- Новый формат запроса погоды, обработку температуры, кэширование и ошибочные ответы — на тестовых данных.
- HTTPS-прокси через локальный TLS-туннель: пароль, специальные символы в пароле, повторное создание сессии, отказ при отсутствии авторизации и недоверенном сертификате.
- Фактическую работу на Raspberry Pi в конце диалога подтвердил пользователь.

## Важные итоги диагностики

- `Python.h` отсутствовал: помог пакет разработки Python.
- `RPi` отсутствовал: для Raspberry Pi 3 нужен `RPi.GPIO` внутри `.venv`.
- Для личного API погоды потребовались новый заголовок **и** переход на GraphQL.
- Открытый порт 443 не доказывает поддержку SOCKS5. Используемый сервер оказался HTTPS-прокси.
- `407` при проверке прокси без учётных данных означает запрос авторизации.
- `tmux` сохраняет процесс при отключении SSH, но не запускает его после перезагрузки. Автозапуск через systemd в этом диалоге не настраивали.

Если ключи, ранее находившиеся в `.env.example`, ещё действуют, их следует перевыпустить: замена значений в файле не удаляет старые коммиты.
